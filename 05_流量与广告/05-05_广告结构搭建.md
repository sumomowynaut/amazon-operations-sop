# 05-05 广告结构搭建

- 版本：v1.0
- 最近更新：2026-08-27
- 维护人：运营负责人
- 证据等级：广告层级为 B 级官方；结构设计原则为 D 级经验

## 1. 模块目的
建立可扩展、可归因、可优化的广告结构，防止广告越投越乱、数据无法复盘。结构搭建是「广告的地基」，结构错，后面所有优化都低效。

## 2. 适用场景
- 新账号 / 新品类 / 新品广告体系规划
- 现有广告结构混乱需要重构
- 多 ASIN、多目标并行投放
- **不适用**：单个活动内的具体竞价调优（05-08）、关键词选择（05-06）

## 3. 核心概念

### 3.1 广告层级【B】
```
广告活动 Campaign
  └─ 广告组 Ad Group
       └─ 投放目标（关键词 / 商品 ASIN / 类目）
```
- 广告活动：控制预算、投放时间、广告类型。
- 广告组：同一活动下按「单一维度」分组，组内共享竞价。
- 投放目标：具体关键词或商品。

### 3.2 结构设计三原则【D 经验】
1. **单一变量**：一个广告组只验证一个变量（一个匹配类型 / 一个核心 ASIN / 一个目标）。
2. **可归因**：任何一笔花费都能定位到「哪个 ASIN、哪个词、哪个匹配、哪个位置」。
3. **按目标分层**：打排名、冲量、防守、清库，目标不同则预算与考核不同，不能混在同一个活动。

### 3.3 三种常用结构模式【D 经验】
| 模式 | 分组维度 | 适用 |
|---|---|---|
| 按匹配类型 | 广泛组 / 词组组 / 精确组 | 关键词从「跑词→精准」分层管理 |
| 按目标 | 打排名 / 防守品牌词 / 冲量 / 清库 | 不同目标不同预算与考核 |
| 按 ASIN | 每个核心 ASIN 一个广告组 | 多 ASIN 且需单品级归因 |

### 3.4 命名规范（必须统一）
- 推荐：`<广告类型>-<ASIN/品牌>-<目标>-<匹配/定向>-<日期>`
- 示例：`SP-B00XXXX-核心词排名-精确-202608`
- 命名不规范 = 数据无法归集，等于白投。

## 4. 核心指标
- **活动/广告组数量**：反映结构复杂度，过多过少都需审视。
- **预算分配**：各目标（排名/防守/冲量/清库）的预算占比，是否与当前阶段匹配。
- **花费占比**：各匹配类型 / 各广告组的花费占比，识别「哪个组在烧钱」。
- **ACOS / TACOS**：见 08-01 / 05-01，按结构分层看才有意义。

## 5. 决策树
- 如果 新品冷启动 → 结构：自动组（跑词）+ 手动精确组（核心词）→ 目标「打排名」
- 如果 成熟品 → 结构：精确组（核心词）+ 品牌词防守组 + 商品定向防御组
- 如果 多 ASIN → 按 ASIN 分广告组，保证单品级归因
- 如果 某广告组花费高但无转化 → 进 05-10 看搜索词 → 否定/收窄，而不是整体砍活动
- 如果 结构混乱无法归因 → 立即按 3.3 重构，先停后改（D 经验）

## 6. 标准操作流程
Step 1：明确每个 ASIN 的广告目标（排名/冲量/防守/清库）。
Step 2：按 3.3 选定结构模式，画出「活动→广告组→投放目标」的层级图。
Step 3：确定命名规范并写进团队文档（可引用本模块 3.4）。
Step 4：在 Amazon Ads Console 按图创建活动与广告组。
Step 5：为每个活动设置预算上限，为每个广告组设置起始竞价。
Step 6：记录结构台账（活动/组/目标/ASIN/预算/起始竞价）。
Step 7：投放后按结构分层导出数据，进入 05-11 优化循环。

## 7. 操作前检查
- 每个 ASIN 的广告目标已明确且可量化。
- 关键词/竞品 ASIN 清单已按 02-03/02-04 准备好。
- 命名规范已确定并通知团队。
- 结构图已画，确认「单一变量」与「可归因」。
- 预算与阶段匹配（新品期可激进，成熟期控利润）。

## 8. 操作后检查
- 结构台账与实际后台一致。
- 每个广告组只有单一变量。
- 花费能定位到 ASIN/词/匹配/位置。
- 无「大杂烩」广告组（多 ASIN 或多目标混在一个组）。

## 9. 成功标准
- 任何一笔花费都能按结构归因到单一变量。
- 各目标预算占比清晰，与当前阶段匹配。
- 团队用同一套命名规范，新人能 5 分钟看懂结构图。

## 10. 失败处理
- 结构无法归因 → 停掉重构，不带着乱结构继续优化。
- 某目标预算长期花不出去或烧穿 → 进 05-08 竞价预算排查。
- 结构复杂度过高 → 合并同类组，保持可维护。

## 11. 常见错误（新人高频）
1. 一个广告组塞多个 ASIN 或多个匹配类型，无法归因。
2. 命名不规范（「广告1」「测试」），事后无法复盘。
3. 打排名与清库混在同一活动，预算与考核打架。
4. 结构一次建太多，维护不过来。
5. 频繁新建活动导致历史数据碎片化。

## 12. 风险
- 资金：结构乱导致预算浪费在无效目标。
- 决策：无法归因导致错误优化决策。
- 效率：结构失控后重构成本高。

## 13. 实战案例
背景：某运营接手一个账号，发现广告活动命名混乱、一个广告组塞 5 个 ASIN，ACOS 高但无法定位问题。
数据（教学假设值）：现有 3 个广告活动，花费分布不均，无法区分哪个 ASIN、哪个词在烧钱。
判断：结构不可归因，继续优化只会更乱。
决策：先停后改，按「按 ASIN 分广告组 + 按匹配类型分层」重构。
操作：画出结构图，统一命名规范 `SP-ASIN-目标-匹配-日期`，重建活动与广告组，记录结构台账。
结果：2 周后能准确定位每个 ASIN 的花费与 ACOS，发现 3 个低效词并否定，整体 ACOS 下降。
复盘：广告问题的一半是「结构问题」，先解决可归因，再谈优化。

## 15. 数据记录模板
字段：活动名 | 广告组名 | ASIN | 目标 | 匹配/定向 | 预算 | 起始竞价 | 创建日期 | 状态 | 备注

## 16. 复盘方法
- 每周：各广告组花费与 ACOS 分层看，识别无效组。
- 每月：结构是否仍匹配当前阶段（新品→成熟切换时调整结构）。
